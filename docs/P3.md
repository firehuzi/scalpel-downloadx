# P3 立项：BT / Magnet / DHT / P2P

> 依据：`docs/BT_SPIKE.md` 的实测结论（2026-10-17）。
> 一句话：**能做的部分很明确，不能承诺的部分也要写清楚。**

## 1. 范围

### 做

- Magnet 链接、`.torrent` 文件下载（BEP-3 / BEP-9 / BEP-10 / DHT）
- 进度（piece 粒度）、速度、peer 数
- 暂停 / 继续（同进程与跨进程恢复）
- 复用现有：任务状态机、优先级队列、事件总线、历史、鉴权 API
- 完成后默认停止做种，可配置做种时长/比率

### 不做

- 不做私有 tracker 的账号体系、不做 PT 站点的比率作弊类功能
- 不解析 DRM/加密流（与 HTTP 侧同一边界）
- 不把 BT 塞进 `DownloadWorker`（两种模型不同，见 §3）

## 2. 与 HTTP 引擎的关系

| | HTTP 引擎 | BT 子进程 |
| --- | --- | --- |
| 恢复单位 | 字节偏移 | **已验证的 piece** |
| 进度语义 | 精确到字节 | 可能重下少量分片 |
| 依赖 | aiohttp（MIT） | libtorrent（**GPL**） |
| 失败模式 | 单连接重试 | peer 全无、tracker 挂、DHT 无路由 |

**结论**：独立进程。理由有三：

1. GPL 依赖与 MIT 主体的边界；
2. C++ 崩溃不拖垮主引擎；
3. 生命周期独立（用户不开 BT 就不起进程）。

## 3. 架构

```
DownloadManager ──(mode="torrent")──▶ BtBridge（父进程）
                                         │  JSON lines over stdin/stdout
                                         ▼
                            downloadx-bt 子进程（libtorrent 会话）
                                         │
                                         ▼
                                   peers / DHT / trackers
```

- 子进程只做"会话管理 + 进度上报"，不含任何 HTTP 下载逻辑。
- 父进程负责：把命令翻译成任务状态、把事件灌进 EventBus、落元数据与历史。
- 通信协议：一行一个 JSON；命令带 `req_id`，响应回填同一个 `req_id`；
  进度事件没有 `req_id`，进事件队列。

## 4. 里程碑

| 里程碑 | 内容 | 验收 |
| --- | --- | --- |
| **P3-1（已完成）** | 子进程 + 协议 + 客户端 + 跨进程暂停恢复 | ✅ 离线测试：本机做种→子进程下载→暂停到 30%→**换新进程**恢复→完成，文件逐字节一致（`tests/test_bt.py`） |
| P3-2 | 接入 `DownloadManager`：`add("magnet:…")` 走 BT，状态映射到现有状态机 | `downloadx add "magnet:…"` 能出现在 `list` 里并可暂停/继续 |
| P3-3 | 队列/优先级/限速复用；做种策略（完成即停、可配置） | 全局并发与限速对 BT 生效 |
| P3-4 | 打包：libtorrent 随包分发（GPL 声明 + 独立进程边界） | 干净机器上 `pip install .` 后 BT 可用 |

## 5. 硬性约束（来自 spike 的教训）

1. **暂停必须 `save_resume_data(flush_disk_cache)`**，否则产出损坏文件（实测校验不通过）。
2. **不要给 `read_resume_data()` 的结果再赋 `ti`**，会把状态冲掉。
3. `alert.params.resume_data` 不可靠，统一用 `lt.write_resume_data_buf(alert.params)`。
4. `seed_mode` 只能走 `flags |= lt.torrent_flags.seed_mode`。
5. 全局 site-packages 可能被杀软拦，依赖走 `--target` 或随包分发。

## 6. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| GPL 传染 | 法律边界 | 独立进程 + 明确声明；不静态链接进主程序 |
| 冷门种子 0 速度 | 用户以为坏了 | UI 区分"在连 peer/无 peer/无路由" |
| 恢复不精确 | 与 HTTP 引擎体验不一致 | 文案写"恢复到最后验证分片"，不承诺字节级 |
| 杀软拦 .pyd | 安装失败 | `--target` 安装 + 文档说明 |
